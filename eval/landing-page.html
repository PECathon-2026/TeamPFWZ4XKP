How it works

Every step runs through one chokepoint.

The model proposes. The extension decides what it may see, what it may do, and what leaves the browser.

Detect locally, in layers.

The content script snapshots the page from an allowlist: scripts, styles, hidden inputs and data-* attributes are dropped, and password fields are never read. Detectors run inside the extension and replace matches with typed placeholders such as [REDACTED:CARD#1].

  • Validated, not just matched. Cards pass Luhn, Aadhaar passes Verhoeff, PAN checks structure and entity type.
  • Hard to obfuscate. Spaced, hyphenated, full-width or zero-width values are normalized first; split values are scanned as one string.
  • Irreversible. No hashes, no last-four. The value-to-placeholder map lives only in extension memory.

One gate. It fails closed.

Exactly one code path calls fetch(). It validates the schema, checks the destination against an allowlist, reconciles the redaction ledger and runs an independent tripwire scan. Any error or timeout blocks the request instead of sending it.

  • Red-team switch. A demo toggle injects a canary into the outgoing payload so you can watch the gate block it.
  • Prompt injection is a data problem. Page text is treated as data. No action exists to read a value, and redacted fields can't be typed into except through the vault.

You approve what matters.

The model returns one structured action, and the validator checks its target exists in the current snapshot. Consequential actions (submit, purchase, credentials, cross-origin, download) need your approval in the side panel.

  • Bound to the element. Tokens are single-use and tied to a fingerprint: accessible name, role, form action, sibling index and text hash.
  • Secrets stay local. An AES-GCM (256-bit) vault fills values through a secretRef; the real value is never sent to the cloud.
  • Your own rules. Add custom regex or CSS-selector rules, scoped by domain, and see why each element was hidden.

Limits

What PrivacyLens does not do.

Knowing the boundary is part of the security model.

  • It does not defend against a compromised browser, operating system or other malicious extensions.
  • It cannot protect secrets you paste into places it doesn't control.
  • Cross-origin iframes, such as embedded payment widgets, are opaque to the DOM path and are default-denied rather than inspected.
  • The sanitizer and gate share detector code, so some failures can be correlated. The ledger check, independent tripwires and held-out evaluation exist to reduce that risk.
  • Chrome stable only. Other browsers are out of scope.

Get started

Run it locally in a few minutes.

Requires Node.js 20+ and Google Chrome. The gateway uses a mock provider by default, so no API key is needed to try it.

1. Install, build and verify

npm install
npm --workspace=@privacylens/extension run build
npm test        # 27 tests; start the gateway first so the e2e suite can connect
npm run eval    # reproduces the table above

2. Start the gateway

npm run gateway   # http://127.0.0.1:8787

Set PROVIDER to anthropic, openai or ollama to use a real model. The default is mock.

3. Load the extension

Open chrome://extensions, enable Developer mode, choose Load unpacked and select apps/extension. Then open the demo store at http://127.0.0.1:8787/demo, open the PrivacyLens side panel and run a task.
